BUET architecture project: an A2 landscape poster about the Shal (Sal, *Shorea
robusta*) forest of Gazipur, Bangladesh. Brief: "types of flora and fauna,
their inter-relationship. Pictorial and diagram-based, less text." The
**interrelationship diagram is the main focus of the whole piece** — the
professor's/reviewer's #1 note was that it needs to dominate the composition.

## Critical CSS bugs discovered (don't reintroduce these)

Spent enormous effort chasing these; write them down so they aren't re-learned
the hard way:

1. **`grid-template-columns: repeat(N, 1fr)` silently breaks inside this
   page's nested flex-in-grid-in-flex structure.** Symptom varies: only the
   first 2–3 of N columns get real width and the rest either vanish, get
   clipped, or push off the container. **Fix that actually works:** use fixed
   `mm` track sizes instead of `1fr`, e.g. `repeat(7, 9.6mm)`. Every grid in
   this poster (`.gallery`, `.tree-row`) must use fixed mm columns, never `1fr`.
2. **`figcaption { width: 100% }` inside a `display:flex; align-items:center`
   parent creates a circular sizing dependency** (the flex parent's width
   depends on the figcaption's content size via align-items:center, but the
   figcaption's width depends on the parent via the percentage) → collapses
   to ~0 width → text renders one character per line. Fix: never set an
   explicit `width` on a figcaption in this layout; let it size to content.
3. **Any `<img>`/`<svg>` with a percentage `width` inside a non-stretched flex
   item is unreliable here.** Fix: give every `<img>` an explicit fixed `mm`
   width/height, ideally **inline** (`style="width:9.6mm;height:9.6mm;..."`
   plus HTML `width`/`height` attrs in px) rather than relying on a CSS class
   rule — inline styles proved immune to whatever was intermittently dropping
   class-level rules in the Artifact viewer specifically (class rules that
   worked in local headless-Chrome screenshots sometimes didn't apply in the
   actual published Artifact — inline style is the reliable fix, applied to
   `chip()` image markup and `<b>`/`<i>` caption text in `trees_row()`/
   `foodweb_html()`).
4. **Nested inline `<svg>` without explicit `width`/`height` attributes,
   placed inside another `<svg>`'s `<g>`, inherits the OUTER svg's viewBox
   size** and renders enormous. Fix: icon functions come in `_inner()` (bare
   shapes, no `<svg>` wrapper — safe to embed inside another svg) and wrapped
   (`svg_wrap()` — full `<svg viewBox="0 0 48 48">`, for plain HTML contexts
   only). Never embed a wrapped icon inside another SVG.
5. **A regular (non-headless) Chrome may already be running under this
   Windows user** — plain `--headless` flags get silently forwarded to that
   live session instead of launching an isolated renderer. Always pass
   `--user-data-dir=<fresh temp dir>` when screenshotting for QA.
6. Verification method that works: launch headless Chrome with an isolated
   `--user-data-dir`, screenshot at `--window-size=2481,1754` (A2 aspect,
   `--force-device-scale-factor=1`), then crop regions with PIL to inspect
   closely. Do this after **every** structural change — visual bugs here are
   easy to introduce and easy to miss at full-page zoom.

## Image pipeline (rembg + OpenCV ink-sketch)

`pip install rembg onnxruntime` (already done, model cached at
`C:\Users\ADIB\.u2net\isnet-general-use.onnx`, ~179MB, downloaded once).

Per user feedback, all flora/fauna/tree images are: background-removed
(`rembg`, `isnet-general-use` model — better than `u2netp` for busy/organic
subjects) → converted to a hand-sketch/ink look via OpenCV (dodge-blend +
adaptive-threshold edges, eroded to thicken linework) → **alpha modulated by
ink density instead of blended toward a flat paper color** (critical: this is
what makes the same PNG work correctly on *any* background color — light
areas are transparent, not opaque-white, so no white halo/box appears when
the page background is a deep color). Tinted uniformly to `--ink` (#182619).

Key tuning (as of last working version, in `sketchify_all.py`):
`gamma=0.45, floor=0.24, boost=1.3` for the cutout path;
`floor=0.22, boost=1.3` for the vignette fallback.
**If images still look "half invisible," raise `floor` further or lower
`gamma`** — the user flagged this once already and it took two rounds of
tuning (`floor` went 0.16 → 0.24) plus a line-thickening `cv2.erode` step to
fix.

**Automatic fallback added:** `rembg` segmentation genuinely fails (near-zero
mask) on a meaningful fraction of the busy/delicate macro shots (especially
thin flowers/climbers on leafy backgrounds, and a lizard well-camouflaged
against concrete). `sketchify_all.py` now measures cutout mask coverage and,
if `< MIN_COVERAGE` (2.8% of canvas), automatically **redoes that image with
`sketch_no_cutout_vignette()`** (whole-frame ink sketch + radial alpha
vignette, no segmentation) instead of shipping a near-blank chip. Check the
run log (prints `[cutout]` vs `[vignette-fallback]` per file) for which
images fell back — worth a quick visual spot check on those specifically.

For the 6 canopy trees specifically: Sal and Jarul had clean isolated-tree-
against-sky source photos → full segmentation cutout. Bohera/Koroi/Amloki/
Sheora source photos are busy (forest interior, urban plaza, orchard, walled
yard) → segmentation produced garbage (scattered twigs) → these use the
no-cutout vignette method deliberately, not as a failure fallback.

## Design decisions (rationale, so they aren't re-litigated)

- **Palette:** deepened from a near-white `#EEF0E3` to a real warm parchment
  `--paper:#E2D9BE` after user feedback #1 ("background isn't supposed to be
  this light... could've been a solid color, but not something out of
  taste"). Ink `#182619`, canopy green `#2F5233`, gold accent `#C69433`,
  clay/threat color `#9C4A28`, human-use accent `#D08A55`.
- **Photos → ink sketches, backgrounds removed:** user feedback #2 and #3
  ("why didn't you remove the backgrounds... could've made it feel more
  real", "can the images be converted into a bit of sketchy-type... BUET
  archi project"). This is now the house style for every species chip, the
  tree typology, and every node in the trophic diagram.
- **Canopy trees are REAL photographs, not illustrations.** First version
  used hand-drawn SVG icon silhouettes because no tree photos were supplied
  — user called this out hard ("you fabricated the images. thats unfair.
  find real images."). Sourced 6 real photos from Wikimedia Commons
  (CC-licensed), one of them (Sal) literally shot in Madhupur reserve forest.
  See "Where things live" above for file locations. If more/better tree
  photos ever become available, swap them into `tree_photos/final/*.png`
  through the same `reprocess_trees.py` pipeline.
- **Interrelationship diagram is a real, named trophic food web, not
  abstract categories.** First version was a radial hub with generic labels
  ("Herbivores", "Predators") — user feedback #5 ("you messed up the whole
  interrelations part... make the arrows so and so that it's clear which
  animal/plant depends on what/why"). Current version (`trophic_svg()` in
  the generator) is a tiered flowchart using actual photographed species:
  Sunlight → Shal Tree → {Five-striped Palm Squirrel, House Sparrow,
  Pollinators, Common Garden Lizard} → {Indian Rat Snake, Common Vine Snake}
  → {Fishing Cat, Grey-headed Fish-eagle}, plus a Decomposers→Soil→Tree
  nutrient loop and a People↔Tree dotted "human use & pressure" edge. Every
  arrow is labeled with the actual mechanism (e.g. "gnaws bark & seeds",
  "preys on rodents, nestlings & eggs"), not just "eats."
- **Composition / solid-void hierarchy:** user feedback #6 and #7. The
  center column was widened from 133mm to 168mm (at the expense of the
  flora/fauna columns, 91mm → 80mm, and the context column, 78mm → 66mm)
  specifically so the interrelationship diagram reads as the hero element,
  not one quadrant among four. Column widths were NOT touched in the round
  below — only the diagram's own fill/color treatment changed.
- **`.trophic-panel` dark background REMOVED (superseding the note above)** —
  second review round, relayed via chat screenshot + a composition
  reference image (a wetland-ecosystem infographic whose hero illustration
  floats directly on white, no color block behind it) plus the specific
  note "the color behind the interrelationship [diagram] — remove that,
  the composition would be fixed." The diagram now floats directly on
  `--paper` like every other element on the sheet, and dominates through
  scale/density/detail instead of a solid ink rectangle. **Do not
  reintroduce a `background`/`box-shadow` on `.trophic-panel`** — this was
  tried first and explicitly rejected. This required flipping every color
  in `trophic_svg()` and its CSS from light-on-dark to dark-on-parchment:
  `.tnode-ring` stroke → `--ink` (was `--panel-fg`), `.tnode-title`/
  `.tspoke-label` fill → `--ink` with an SVG text-halo (`paint-order:stroke;
  stroke:var(--paper);stroke-width:3px`) for legibility over crossing lines
  — since without a uniform dark backing, text now sits on a busy paper
  background and needs its own contrast trick, `.tnode-sub` fill → `--moss`
  (gold-on-paper measured ~1.9:1 contrast, too low — moss is the poster's
  established italic/sub-label color elsewhere, e.g. `.tree-chip i`),
  `.trophic-eyebrow`/`.trophic-sub` → `--canopy`/`--moss` (matching the
  other three columns' eyebrow treatment, which is what makes the center
  column now read as integrated with the page rather than a dropped-in
  insert), arrow marker fill and icon `currentColor` → hardcoded `#182619`
  (ink). **Exception:** the Shal Tree hub's caption still sits on its own
  small solid dark plate drawn directly over the tree photo (`fill="var(
  --ink)" opacity="0.82"` rect) — that plate provides its own local
  contrast regardless of panel color, so it kept light text. Given its own
  dedicated classes (`.tnode-title-onplate`, `.tnode-sub-onplate`, still
  `--panel-fg`/`--gold`) instead of sharing `.tnode-title`/`.tnode-sub`,
  specifically so this one exception doesn't get lost/reverted next time
  the general node-label colors change.
- **Old bottom "simplified food web" strip was removed** once the main
  diagram became a real, comprehensive food web — it was fully redundant.
- **Chips have no border/white box anymore** (they did originally, to frame
  opaque JPEG thumbnails) — now that images are transparent ink cutouts,
  a border would fight the hand-drawn look, so `.chip img` is borderless,
  `object-fit:contain`.

## Content reference (accurate, don't re-derive)

Species lists, Latin binomials, and forest-layer facts were sourced from two
papers that live in the project root and were read in full early in this
session: `InternationalForestryReview2.pdf` (Alam et al. 2008, Sal forest
sustainability, Bhawal National Park/Gazipur specifically) and
`ssrn-4890745.pdf` (Rahman, Dharmapur Sal forest biodiversity checklist —
this is where the *exact* species list matching the supplied photos comes
from: 20 shrubs + 13 climbers + 7 mammals + 20 birds + 13 reptiles/amphibians
= 73, matching the photo counts exactly). Full species metadata (local name,
common name, binomial, filename) is hardcoded in `generate_poster.py` as
`SHRUBS`, `CLIMBERS`, `MAMMALS`, `BIRDS`, `HERPS`, `TREES` — treat that as
the canonical list rather than re-deriving from the PDFs again.
